==========================================================
ПАМЯТКА: Как запустить проект ProductionApp и продолжить разработку
==========================================================

ПРИВЕТ! Чтобы проект запустился на твоем компьютере и база данных заработала, 
выполни шаги ниже. Проект использует современный подход (Entity Framework Core + Миграции), 
поэтому важно следовать инструкции.

----------------------------------------------------------
ШАГ 1. ЧТО ДОЛЖНО БЫТЬ УСТАНОВЛЕНО
----------------------------------------------------------
1. Visual Studio 2022 версии 17.14 или Visual Studio более новой версии.
   ВАЖНО: При установке должна быть выбрана рабочая нагрузка 
   «Разработка классических приложений .NET» (.NET desktop development) 
   с компонентом .NET 8.0 SDK.
2. SQL Server Management Studio (SSMS) - для просмотра базы данных.
3. SQL Server LocalDB (обычно ставится вместе с Visual Studio).

----------------------------------------------------------
ШАГ 2. ОТКРЫТИЕ ПРОЕКТА
----------------------------------------------------------
1. Открой файл решения (.sln) в Visual Studio.
2. Проверь файл appsettings.json (он в корне проекта). 
   В нём должна быть строка подключения к базе:
   {
     "ConnectionStrings": {
       "DefaultConnection": "server=(localdb)\\mssqllocaldb;database=ProductionDB;Integrated Security=true;TrustServerCertificate=true;"
     }
   }
   *Если файла нет — создай. В свойствах файла (в панели справа) 
   поставь «Копировать в выходной каталог» -> «Копировать более позднюю версию».

----------------------------------------------------------
ШАГ 3. ПРОВЕРКА ПАКЕТОВ (NuGet)
----------------------------------------------------------
1. Нажми ПКМ по проекту -> «Управление пакетами NuGet».
2. Убедись, что установлены пакеты версии 8.0.x (если нет — установи):
   - Microsoft.EntityFrameworkCore.SqlServer
   - Microsoft.EntityFrameworkCore.Tools
   - Microsoft.Extensions.Configuration
   - Microsoft.Extensions.Configuration.Json
   - Microsoft.Extensions.Configuration.Binder

----------------------------------------------------------
ШАГ 4. СОЗДАНИЕ БАЗЫ ДАННЫХ
----------------------------------------------------------
1. При первом запуске приложение применит миграции и создаст базу ProductionDB.
2. Для ручного применения миграций можно выполнить Update-Database
   в консоли диспетчера пакетов Visual Studio.

----------------------------------------------------------
ШАГ 5. ЗАПУСК И ПРОВЕРКА
----------------------------------------------------------
1. Нажми F5 в Visual Studio. Программа запустится.
2. Открой «Регистрация изделия» и заполни поля через шесть кнопок.
   Кнопка «Сервисные работы» открывает списки компонентов и работ.
   Вернись к регистрации и нажми «Сохранить изделие».
3. Открой SSMS, подключись к (localdb)\mssqllocaldb.
4. Нажми ПКМ на «Базы данных» -> «Обновить». 
   Там появится ProductionDB с твоими данными.

==========================================================
ВАЖНЫЕ НЮАНСЫ ДЛЯ ДАЛЬНЕЙШЕЙ РАЗРАБОТКИ
==========================================================

1. ДОБАВЛЕНИЕ НОВОГО ПОЛЯ В БАЗУ (например, «Цена» в Product.cs):
   - Добавь свойство в класс (public decimal Price { get; set; }).
   - Открой Консоль диспетчера пакетов.
   - Введи: Add-Migration AddPriceToProduct
   - Введи: Update-Database
   (Всегда создавай новую миграцию при изменении моделей!)

2. ЕСЛИ ПРИЛОЖЕНИЕ НЕ ПОДКЛЮЧАЕТСЯ К БАЗЕ:
   - Открой «Подробности ошибки» на главной и нажми «Повторить подключение».
   - При стандартных настройках приложение ищет файлы ProductionDB.mdf
     и ProductionDB_log.ldf, если база отсутствует в списке LocalDB.
     Если оба файла найдены, приложение подключает их при запуске.

3. ГДЕ ХРАНИТСЯ СТРОКА ПОДКЛЮЧЕНИЯ:
   - Только в appsettings.json. Не меняй её в коде.
   - В App.xaml.cs есть метод GetDbContext(). Используй его для работы с БД:
     using (var db = App.GetDbContext()) { ... }

4. СТРУКТУРА БАЗЫ (3НФ):
   - Products — главная таблица.
   - ProductComponents — компоненты (связаны с ProductId).
   - ProductServiceWorks — работы (связаны с ProductId).
   - При удалении изделия его компоненты и работы удаляются автоматически (Cascade).

5. ПРОВЕРКА ПРИ СОХРАНЕНИИ ИЗДЕЛИЯ:
   - Нельзя сохранить изделие, если не заполнено описание неисправности 
     и не прикреплен файл акта (должно быть хотя бы одно из двух).

Удачи в разработке!
